# AlgoQuant examples

Six runnable technical-analysis examples, moved from the AlgoQuant demo module. Java package names and strategy classes are preserved. The library implementation is supplied by the public, obfuscated combined `tech.nmfin:algoquant-dist:3.3.0-SNAPSHOT` JAR.

## Setup

Use JDK 8 and Maven 3.9.9. Add this server entry to `~/.m2/settings.xml` (Windows: `%USERPROFILE%\\.m2\\settings.xml`), merging it with existing settings:

```xml
<settings><servers><server>
    <id>github-nm-packages</id>
    <username>YOUR_GITHUB_USERNAME</username>
    <password>YOUR_GITHUB_TOKEN</password>
</server></servers></settings>
```

Use your own GitHub personal access token **(classic)** with `read:packages`. No private source access or NM internal token is needed.

Put a valid NM license at `license/nm.lic`, or pass `-Dnm.license=/absolute/path/nm.lic` when running. A [starter trial license](https://github.com/nmltd/new-algoquant-project/blob/main/license/nm.lic) is already public; its validity and entitlements are enforced by the library. The license is loaded explicitly and is not embedded in the examples JAR.

## Build and run

```bash
mvn -U clean verify
mvn exec:java
```

The default is `SMA2Demo010`. Choose another example:

```bash
mvn exec:java -Dexec.mainClass=tech.nmfin.algoquant.demo.model.technical.ChaikinMoneyFlowDemo
mvn exec:java -Dexec.mainClass=tech.nmfin.algoquant.demo.model.technical.SMA2DynamicDemo -Dexec.args="--quick"
```

| Class | Demonstrates |
|---|---|
| SMA2Demo010 | Two moving-average crossover simulation |
| SMA2Demo011 | Crossover simulation with currency conversion |
| SMA2Demo020 | The simulation-template API |
| AccumulationDistributionLineDemo | An ADL-based strategy |
| ChaikinMoneyFlowDemo | A CMF-based strategy |
| SMA2DynamicDemo | Periodic parameter calibration and CSV report export |

All examples default to **deterministic synthetic OHLC/volume data**, generated by `DemoSupport`. Prices are keyed by calendar date, so a calibration window sees the same historical values as the main simulation. No downloaded dataset is required. Synthetic results demonstrate the APIs; they are not evidence of historical trading performance.

Charts are disabled by default. Options may be combined:

- `--charts`: open desktop charts where the demo has a plotter; requires a graphical environment.
- `--live`: use Yahoo historical data instead of synthetic inputs; requires network access and available symbol history.
- `--quick`: shorten the dynamic calibration example to one parameter combination over three months. The full dynamic run searches 16 combinations over several years and can take considerably longer.

For example:

```bash
mvn exec:java -Dexec.args="--charts"
mvn exec:java -Dexec.mainClass=tech.nmfin.algoquant.demo.model.technical.SMA2Demo011 -Dexec.args="--live --charts"
```

Live examples use META rather than the retired FB ticker and AAPL rather than the historical JWN example. Yahoo availability and data revisions can change results. The dynamic example uses a fresh simulator and fresh performance measures for each parameter combination.

## Offline validation

After building, run all six examples:

```bash
bash scripts/run-offline.sh
```

The script uses the packaged public dependency in `target/lib/`, disables desktop charts, and bounds each run to five minutes. Each simulation checks for a nonempty, finite NAV series and prints its execution count. Dynamic results are written under `log/`. CI compiles and runs all six with only its built-in GitHub token; no private repository secrets or live market-data calls are used.

The example sources retain their original copyright and license notices. The underlying AlgoQuant/NM Dev libraries require a valid NM license.

## SMA2 web application

An interactive US-stock SMA2 backtest application is included separately from the six demos. See [web setup and Cloud Run deployment](web/README.md). Intended hostname: `optim.nmfin.tech`.

### Web application folders

SMA2 server code lives in `src/main/java/tech/nmfin/algoquant/web/sma2`, its tests in the matching test package, and its frontend in `src/main/resources/web/sma2`. Shared tools-directory resources remain in `src/main/resources/web`. Give each future application its own folder under `web`.
